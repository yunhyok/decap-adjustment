# Decap Adjustment

<img src="assets/app.png" width="112" alt="회로와 커패시터, 거리 순서를 표현한 Decap Adjustment 아이콘">

Windows에서 Excel의 decap 활성 상태와 부품 배치를 조정하는 한국어 데스크톱 앱입니다. **미리보기 → 수량 검증 → 새 파일 저장** 순서로 동작합니다. 입력 파일은 컴퓨터 안에서 처리하며 서버로 전송하지 않습니다.

## 설치

[최신 GitHub Release](https://github.com/yunhyok/decap-adjustment/releases/latest)의 `DecapAdjustment-1.0.1-Setup-x64.exe`를 내려받아 실행하세요. Python이나 개발 도구는 필요 없습니다.

- Windows 10/11 x64, 사용자 계정 단위 설치. 관리자 권한 불필요.
- 시작 메뉴와 선택한 경우 바탕화면에 바로가기가 생성됩니다.
- Windows 설정의 **설치된 앱 → Decap Adjustment → 제거**로 삭제합니다.
- 설치파일은 현재 **코드 서명되지 않았습니다**. Windows가 알 수 없는 게시자로 표시할 수 있습니다. Release의 SHA-256 파일로 다운로드 파일을 확인할 수 있습니다.
- Windows 7, ARM64 네이티브 실행, macOS 설치 패키지는 지원하지 않습니다.

## 사용 순서

1. **파일** 탭에서 distance와 refdes `.xlsx`를 선택합니다. 자동 감지된 시트, 헤더 행, 열을 확인하고 필요한 경우 직접 수정합니다. 미리보기는 Excel처럼 A·B·C 열과 행 번호로 표시하며 빈 셀의 위치도 유지합니다. 가로 스크롤과 열 경계 드래그로 오른쪽 열을 확인하고, 셀을 클릭하면 아래 값 표시줄에서 전체 내용을 읽고 복사할 수 있습니다. 파란색 행이 선택한 헤더입니다. 감지 후보가 여럿이면 후보 목록에서 선택합니다. 헤더가 없는 표는 데이터 바로 위 행을 헤더 행으로 지정하고 열을 수동 연결합니다.
2. **증감 명령** 탭에서 직접 입력 또는 명령 Excel을 선택합니다. 두 방식을 동시에 적용하지 않습니다. 직접 입력은 NET, 정확한 Component 이름, `A-2,D+1` 같은 명령을 입력해 추가합니다.
3. 기본 동작은 **status 증감**입니다. 부품 위치도 정렬하려면 **배치 · 변환** 탭에서 재배치를 켜고 대상 NET을 직접 선택합니다. 부품 목록은 작은 용량부터 큰 용량순이며 위/아래 버튼으로 가까운 자리 → 먼 자리의 순서를 바꿀 수 있습니다. 제외한 부품은 재배치하지 않습니다.
4. **계산 · 미리보기**를 누릅니다. RefDes별 기존/결과 부품과 status, distance, 선택 근거, NET/부품별 기존·예상·결과 활성 수량을 검토합니다. 오류가 있으면 전체 계산을 취소하고 저장을 막습니다.
5. **결과 저장**으로 대상 폴더를 선택합니다. 새로운 `decap_날짜_시간_식별자` 폴더가 생성됩니다.

앱의 **합성 예제 불러오기**로 실제 제품 파일 없이 흐름을 확인할 수 있습니다. `examples/`의 모든 이름과 수치는 가상의 데이터입니다.

## 입력 형식

열의 위치와 헤더 행은 고정하지 않습니다. `RefDes Name`, `REFDES`, `Net Name`, `NET`, `Activation Status`, `Component`, `Distance [um]` 같은 헤더를 자동 감지합니다. 시트 이름도 고정하지 않습니다. 인식하지 못한 표는 열을 `A`, `B` 또는 `1`, `2`로 지정하세요.

| 파일 | 필수 정보 |
| --- | --- |
| refdes | RefDes, NET, 현재 Component, 현재 Status |
| distance | RefDes, NET, 0 이상의 숫자 Distance |
| 명령 (가로) | NET 또는 Channel/SITE, 부품명별 명령 열 |
| 명령 (세로) | NET 또는 Channel/SITE, Component, Command |

실제 NET 열이 없으면 기본 `U{site}_{channel}`로 조합합니다. 수동 매핑에서 `{channel}/{site}` 등으로 변경할 수 있습니다. 사용자가 지정하지 않은 열은 읽기/계산에 사용하지 않습니다. distance 단위는 입력의 숫자 그대로 표시합니다. 하나의 표 안에서 같은 단위를 사용해야 합니다.

**현재 부품과 상태의 기준은 refdes입니다.** distance 표의 과거 부품명은 무시하고 RefDes+NET을 정확히 연결합니다. 이름의 공백, 오타, 중복 또는 모호한 일치는 자동으로 추측해 합치지 않습니다. 명령표 이름이 다를 때는 **명시적 부품명 별칭**에서 `명령 이름=실제 이름`을 지정하세요.

## 증감과 배치의 의미

| 명령 | 선택 방향 | 실제 변경 |
| --- | --- | --- |
| `A+2` | 가까운 자리부터 | 현재 Disabled인 지정 부품 2개 → Automatic |
| `D+2` | 먼 자리부터 | 현재 Disabled인 지정 부품 2개 → Automatic |
| `A-2` | 가까운 자리부터 | 현재 Automatic인 지정 부품 2개 → Disabled |
| `D-2` | 먼 자리부터 | 현재 Automatic인 지정 부품 2개 → Disabled |

이미 목적 상태인 자리를 증감 수량으로 세지 않습니다. 콤마는 순차 실행이며 다음 명령이 앞선 변경 상태를 봅니다. Excel 명령은 행, 열 순서로 처리합니다. 같은 NET/Component의 중복 명령 행은 충돌 오류입니다. 의도적인 순차 명령은 한 셀에 콤마로 합치세요. 같은 distance는 Excel 행 번호가 작은 자리부터 선택하고 선택 경계의 동률을 경고합니다.

재배치는 명령 처리 **후**에 수행합니다. 선택 NET/부품의 Automatic과 Disabled 자리를 모두 distance 오름차순으로 놓고, **Component+Status 쌍**을 설정한 부품 우선순위대로 이동합니다. 따라서 물리 RefDes/NET과 부품별 활성 수량은 유지됩니다. 증감으로 먼저 선택한 RefDes와 최종 활성 위치가 달라질 수 있으며, 이 이동도 미리보기에 기록됩니다. 순수 status 증감만 원하면 재배치를 끄세요.

용량 자동 인식 예: `CAP_0603M_10NF` → 10nF, `CAP_0603M_4U7F` → 4.7µF, `CAP_1004_1UF___10` → 1µF. 패키지/식별 숫자만으로 용량을 추정하지 않습니다. 미인식 용량은 pF 단위로 수정하거나 순서를 직접 이동하세요. 용량 수정은 현재 포함된 부품을 다시 용량순으로 정렬합니다.

## 부족분 변환

변환은 기본으로 꺼져 있습니다. **권장 3가지 규칙 채우기**는 각 용량에 대응하는 부품이 하나씩 있을 때만 정확한 부품명으로 규칙을 제안합니다. 목록을 확인한 다음 **아래 변환 규칙 사용**을 켜세요. 부품명이 여러 개면 규칙 추가 화면에서 대상/원본을 직접 지정합니다.

| 추가할 용량 | 부족할 때 가져올 자리 | 활성 수 보정 |
| --- | --- | --- |
| 4.7µF | 같은 NET의 Disabled 1µF 중 먼 자리 | 없음 |
| 1µF | 같은 NET의 100nF 중 먼 물리 자리, Disabled 포함 | Automatic 100nF를 가져오면 가장 가까운 남은 Disabled 100nF를 활성화 |
| 10nF | 같은 NET의 Disabled 100nF 중 가까운 자리 | 없음 |

보정 자리도 부족하면 전체 계산을 취소합니다. 사용자 정의 규칙에서 Automatic 부품을 가져오면서 보정을 끄면 원본 부품의 활성 수가 줄어드는 사실을 경고와 수량표에 표시합니다. 과거의 부품명 일괄 교체나 비활성 부품 복구는 자동 적용하지 않습니다.

## 저장과 검증

- `updated_refdes.xlsx`: 원본 ZIP 안에서 바뀐 Component/Status 셀만 수정합니다. 나머지 시트, 셀 값/수식/서식, 열 너비, 인쇄 설정과 기타 ZIP 멤버를 보존합니다.
- `component_changes.xlsx`: 부품명이 바뀌었을 때만 생성하며 `RefDes`, `Component` 두 열입니다.
- `validation.xlsx`: 수량, 변경 목록, 증감/변환/보정/재배치 이력, 경고와 검증 결과.
- `audit.json`: 동일한 추적 정보를 다른 도구에서 읽을 수 있는 형태로 저장합니다.

원본과 기존 결과를 덮어쓰지 않습니다. 미리보기 이후 입력 파일이 바뀌면 다시 읽고 계산해야 합니다. 저장 중 실패하면 임시 결과 전체를 정리합니다. 저장 시에도 행 식별자와 변경 목록을 원본과 다시 대조합니다.

검증은 RefDes/NET/물리 자리 수 불변, 부품별 예상/결과 수량 일치, 지정 범위 밖 부품과 NET 불변을 확인합니다. 누락된 distance, 중복 RefDes/거리 키, 명령 충돌, 부족 수량, 보정 실패를 구체적으로 표시합니다. Enabled 등 다른 상태의 행은 명령/재배치 대상 밖에서 그대로 보존하며 대상으로 삼으면 오류가 납니다.

지원 입력은 `.xlsx`입니다. 매핑한 식별자/부품/status/distance/명령 열의 수식은 거부하므로 별도 복사본에 계산된 값을 넣어 사용하세요. 매핑하지 않은 다른 셀의 수식은 그대로 보존합니다. 문서 암호화, 매크로 통합 문서, 전자 서명 유지 기능은 제공하지 않습니다.

## 개발과 재현 가능한 패키징

Python 3.12.10 x64 기준입니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-build.txt
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python run_app.py
```

Windows 설치파일은 [패키징 안내](packaging/README.md)에 따라 빌드합니다.

```powershell
.\packaging\build.ps1
```

스크립트는 별도 빌드 환경 생성, 자동 테스트, PyInstaller, Inno Setup, 실제 설치→앱 자체 검사→창 초기화→아이콘/바로가기→제거 검증을 수행합니다. 출력은 `outputs/`에 생성됩니다. 기존 설치나 같은 이름의 바탕화면 바로가기가 있으면 검증이 덮어쓰지 않고 중단합니다.

`v1.0.0` 형식 태그를 push하면 Windows Release workflow가 같은 검증을 수행하고 설치파일과 체크섬을 GitHub Release에 첨부합니다. `workflow_dispatch`로도 빌드할 수 있습니다. 의존성은 버전을 고정했으며, 바이너리가 비트 단위로 동일하다는 보장은 하지 않습니다.

테스트는 합성 데이터만 사용하며 계산 규칙, 보정 실패의 원자적 취소, 변경 범위, 순서 변경, 수량 검산, 헤더 변형, 원본 XML/수식/서식 보존, 저장 실패, GUI 미리보기 무효화까지 검사합니다. 고객 Excel, 실제 NET/RefDes, 로컬 작업 로그 및 인증정보는 저장소나 설치 패키지에 포함하지 않습니다.
